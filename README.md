# Mini-PDM «Состав изделия»

Тестовое задание на разработку упрощённой системы учёта конструкторского состава изделия.
Приложение позволяет импортировать данные из набора CAD-файлов, хранить объекты и их версии в PostgreSQL, строить дерево состава, формировать сводную спецификацию и рассчитывать массу изделия.
CAD-файлы из задания являются JSON-документами с расширениями `.a3d` и `.m3d`.

## 2. Структура Solution

MiniPdm.Domain
Модели предметной области: объекты, версии, BOM-связи, CAD-модели, состояния и результаты расчётов.

MiniPdm.Application
Бизнес-логика приложения: импорт, проверки, версии, расчёт массы, спецификация и дерево состава.
Application не работает напрямую с файловой системой и JSON.

MiniPdm.Infrastructure
Работа с внешними ресурсами:
- PostgreSQL
- Dapper/Npgsql
- JSON CAD-файлы
- файловая система

MiniPdm.Wpf
Пользовательский интерфейс на WPF и MVVM.

MiniPdm.Tests
Unit-тесты бизнес-логики на xUnit.

## 6. Архитектура
В проекте используется простое разделение ответственности:
WPF / MVVM
Application
Infrastructure
PostgreSQL / CAD JSON

Domain содержит модели предметной области и не зависит от инфраструктуры или WPF.
Зависимости передаются через конструкторы. Регистрация зависимостей выполняется в App.xaml.cs
Такое разделение выбрано для того, чтобы бизнес-логику можно было тестировать отдельно от интерфейса, PostgreSQL и файловой системы.

## 7. Абстракция CAD-системы
По условию задания работа с CAD должна быть отделена от основной логики приложения.
Для этого используются интерфейсы:
ICadFileLocator
ICadDocumentReader

ICadFileLocator отвечает за получение списка CAD-файлов.
ICadDocumentReader отвечает за чтение одного документа.
Текущая реализация:
JsonCadDocumentReader
читает JSON-файлы.

Application-слой не знает о JSON и не обращается напрямую к файловой системе.

## 8. Предметная область
Поддерживаются три типа объектов:
Assembly
Part
StandardPart

### Assembly
Сборка. Имеет обозначение и состав. Масса рассчитывается по составу.
### Part
Деталь. Имеет обозначение, наименование, материал и массу.
### StandardPart
Стандартное изделие. Не имеет обозначения и идентифицируется по наименованию. Масса обязательна.
Для Assembly и Part используется формат обозначения:
^[А-ЯЁ]{4}\.\d{6}\.\d{3}$

## 9. Версии и состояния
Версия объекта имеет одно из состояний:
InWork
Approved
Cancelled

Разрешены переходы:
InWork - Approved
InWork - Cancelled
Approved - Cancelled

Обратные переходы запрещены.
Текущей является последняя версия, которая не была аннулирована.
При повторном импорте:
- если данные не изменились — новая версия не создаётся
- если текущая версия InWork — она обновляется
- если текущая версия Approved — создаётся новая версия InWork
- если все старые версии аннулированы — создаётся новая версия

## 10. Импорт CAD

Импорт запускается из главного окна кнопкой «Импорт CAD».
Необходимо выбрать папку cad-export.
Импорт выполняется в транзакции базы данных. 
Ошибка одного файла не останавливает обработку остальных файлов.
Во время импорта проверяются:

- версия формата
- тип объекта
- наименование
- формат обозначения
- обязательность материала
- наличие и корректность массы
- количество компонентов
- дублирование обозначений
- отсутствующие файлы
- отклонённые дочерние объекты
- циклические ссылки

### Правила ошибок

- файл с ошибкой отклоняется
- дублирующиеся обозначения приводят к отклонению всех конфликтующих файлов
- количество компонента должно быть больше нуля
- отсутствующий компонент отклоняет родительскую сборку
- отклонённый дочерний объект отклоняет родительскую сборку
- циклическая ссылка отклоняет объекты цикла и зависимые от них сборки
- деталь без массы импортируется с предупреждением
- стандартное изделие без массы отклоняется

После завершения импорта пользователь получает отчёт с результатом по каждому файлу.

## 13. Дерево состава
Дерево состава получается одним SQL-запросом с рекурсивным CTE PostgreSQL.
Отдельный запрос из C# для каждого уровня дерева не выполняется.

## 14. Сводная спецификация и расчёт массы
Для выбранной сборки приложение строит плоскую спецификацию.
Если компонент находится на нескольких уровнях, количества перемножаются по каждому пути и затем суммируются.

Например:
Подсборка × 3
Деталь × 4

Итоговое количество детали:
3 × 4 = 12


Масса рассчитывается на основании текущих версий дочерних объектов.
Если у компонента нет массы, приложение не возвращает неполную сумму. 
Пользователю показывается информация о компонентах без массы.
